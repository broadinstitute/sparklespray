# 12. Glossary

| Term                                 | Meaning                                                                                                                                                                                                                 |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Job**                              | A user-submitted unit of work, comprising one or more Tasks, bound to a WorkPool. Immutable once created.                                                                                                               |
| **Task**                             | A single command execution within a Job — one Docker container run on a worker VM. Has its own `status` lifecycle.                                                                                                      |
| **WorkPool**                         | A named pool of worker VM capacity with a fixed spec (machine type, region/zones, service account, resource capacity, scaling limits). Jobs/Tasks target a WorkPool; the monitor provisions Workers into it.            |
| **Worker**                           | A running process (`sparkles worker`) on a VM, registered in Firestore, claiming and executing Tasks until it lingers out or is preempted.                                                                              |
| **BatchAPIRequest**                  | A Firestore record of one GCP Batch `Job` (VM group) the monitor created to provision Workers for a WorkPool.                                                                                                           |
| **Monitor**                          | The autoscaler/watchdog pollers. Runs inside `sparkles serve`, or standalone via `sparkles dev monitor`.                                                                                                                |
| **Dashboard-backend**                | The REST API server (and embedded UI) that the CLI and dashboard talk to; implements `openapi.yaml`. Runs inside `sparkles serve`, or standalone via `sparkles dev dashboard-backend`.                                  |
| **Serve**                            | `sparkles serve` — the deployment entry point, running the monitor and dashboard-backend together in one process.                                                                                                       |
| **Status**                           | A raw field on a primary Firestore document (Job/Task/Worker/BatchAPIRequest), owned by exactly one writer, reflecting that entity's own lifecycle.                                                                     |
| **State**                            | A derived/aggregated field on a summary/history document (WorkPoolSummary/JobSummary), recomputed periodically by a dedicated poller from primary documents.                                                            |
| **Event**                            | An append-only record in the `Events` Firestore collection / `sparkles-events` Pub/Sub topic, mirroring every lifecycle transition; the sole mechanism for one collection's owner to influence another's derived state. |
| **Zombie (worker)**                  | A Worker whose heartbeat has expired (from the monitor's perspective) but which GCP still reports as running — a cluster-reconciler anomaly, distinct from a normally-preempted VM.                                     |
| **Halted (workpool)**                | A sticky WorkPool state that blocks further provisioning after `MaxConsecutiveFailedBatches` consecutive batch failures; reset only by a new job submission.                                                            |
| **Idle / Ok / Unhealthy (workpool)** | The non-halted WorkPoolSummary health states: `idle` (no non-terminal tasks), `ok` (normal), `unhealthy` (recent incidents, not yet halted).                                                                            |
| **Preemptible VM**                   | A discounted GCE VM that GCP may reclaim at any time; preferred by the provisioning poll up to `MaxPreemptibleWorkerAttempts` before falling back to on-demand.                                                         |
| **Linger time**                      | How long an idle Worker stays running (waiting for more work) before shutting itself down, configurable per WorkPool (`LingerTimeSec`).                                                                                 |
| **Resources**                        | A `map[string]float64` (e.g. `slots`, `mem`) used both as capacity a Worker advertises and as requirements a Task declares; a mismatch pre-fails the Task without a wasted claim attempt.                               |
| **Batch API emulator**               | A local HTTP server (`monitor/emulator`) standing in for the real GCP Batch API in tests/dev, paired with `remote_batch_client.go`.                                                                                     |
| **Functional test**                  | An end-to-end test running real `sparkles worker`/monitor processes against local Firestore/Pub-Sub/GCS emulators, without any real GCP dependency.                                                                     |
